随着 AI Agent 开始承担多轮对话、长周期任务和复杂协作，记忆系统已经从“可选的附加组件”变成了基础设施。

Agent Memory 与 RAG 确实存在交叉：两者都可能使用向量表示、外部存储和检索。但它们并不等价。**RAG 主要解决外部知识接入与检索，Agent Memory 维护的则是一种持续变化的认知状态。**它不仅要存储信息，还要在交互过程中更新、整合、纠错和抽象，从而让 Agent 在长期任务中保持身份或目标的连续性。

## 一、记忆的三个层级

我把 Agent 能利用的信息粗略分成三个层级：

| 层级 | 载体 | 作用 |
|---|---|---|
| Token level | 当前上下文窗口 | 保存本轮任务正在使用的指令、消息和中间结果 |
| Parameter level | 模型参数 | 保存训练阶段形成的通用知识与能力 |
| Latent level | 向量表示或隐藏状态 | 保存可被相似度检索或后续计算重新调用的语义状态 |

这三个层级的生命周期不同。上下文适合短期工作，参数知识稳定但不容易即时修改，向量与外部状态则适合跨会话保存和按需召回。

## 二、为什么 Agent 需要记忆

记忆可以粗分为长期记忆和短期记忆。

### 长期记忆

长期记忆至少包含两类内容：

- **事实性知识记忆**：用户偏好、项目事实、环境状态和已经确认的结论。
- **经验记忆**：曾经采用过的步骤、失败原因、有效策略，以及逐渐沉淀成 Skill 的能力。

### 短期记忆

短期记忆更接近会话中的工作记忆。它只服务于当前任务，用来维护目标、约束、计划、中间结果和待验证假设。任务结束后，其中只有真正具有复用价值的部分才应该进入长期记忆。

因此，记忆系统不能只是“保存所有聊天记录”。真正困难的是判断：什么值得留下，什么已经过期，什么需要被新事实覆盖。

## 三、记忆管理是一套状态操作

从工程角度看，记忆管理很像数据库的增、删、改、查。在 Mem0 一类框架中，可以进一步归纳为四种动作：

- `add`：写入新的事实或经验。
- `update`：用更准确、更新的信息修正旧记忆。
- `delete`：删除错误、敏感或已经失效的内容。
- `noop`：当前信息没有长期价值，不做写入。

`noop` 很重要。如果系统遇到任何信息都写入，记忆会迅速膨胀，检索结果也会被大量低价值内容污染。

## 四、Agent Memory 与 RAG 的边界

RAG 更像一个面向知识的外挂读取系统：先把文档切片和向量化，再根据问题检索相关片段，把结果交给模型生成回答。

Agent Memory 则要处理状态的完整生命周期：

```text
交互事件
  ↓
判断是否值得记忆
  ↓
新增 / 更新 / 删除 / 不处理
  ↓
压缩、抽象与冲突消解
  ↓
在未来任务中按目标召回
  ↓
根据新反馈再次修正
```

两者可以共用存储和向量检索，但 Agent Memory 还必须理解时间、主体、目标、可信度和信息冲突。仅有向量数据库并不会自动产生这些能力。

## 五、我关注的未来方向

### 1. 面向自动化的记忆设计

目前很多系统仍依赖人工编写 Prompt 和规则，决定什么时候写、怎样更新、何时检索。未来更重要的问题，是让模型学会自主维护记忆。[Memory-R1](https://arxiv.org/abs/2508.19828)已经开始探索这一方向，也给了我很多启发。

### 2. 强化学习与记忆系统融合

可以利用奖励信号优化记忆提取和更新策略，让 Agent 通过任务结果学习什么应该记住、什么应该忘记，而不是永远依赖固定启发式规则。

### 3. 多模态记忆

记忆需要从文本扩展到视觉、听觉和其他感知信息。难点不仅是保存多模态数据，还包括跨模态抽象、关联与可靠召回。

### 4. 多 Agent 共享记忆

多个 Agent 协同时，需要共享环境状态、团队决策和可复用经验，同时避免重复劳动、权限越界和相互覆盖。共享记忆既是协作层，也是治理层。

## 结语

真正成熟的 Agent 必须超越“向量数据库 + 检索”，建立具备写入、沉淀、抽象、纠错和遗忘能力的动态记忆子系统。

启发式记忆仍然有现实价值，也能在具体任务中取得很好的效果，但它很难凭一套固定规则适配所有领域。下一阶段的关键，不只是让 Agent 记得更多，而是让它能够判断**哪些信息值得记、如何形成稳定经验，以及什么时候应该修正自己。**
